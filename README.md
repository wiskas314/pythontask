#  Async Proxy Server
Асинхронный HTTP/HTTPS прокси-сервер с возможностью кэширования, лимитирования трафика и дампа сетевых запросов.

## Server parameters
* host=127.0.0.1 Хост для запуска прокси-сервера

* port=8080 Порт для прослушивания входящих соединений

* log_file=proxy.jsonl Путь к файлу для сохранения JSON-логов соединений

* cache_size=0 Максимальное число записей в кэше (по умолчанию 0 — отключено)

Run
```bash
python web.py
```
Advanced Example
```bash
python web.py --host 127.0.0.1 --port 8080 --cache-size 200 --traffic-limit 52428800 --dump-dir ./dumps --verbose
```

## Core modules configuration
Если вам нужен дополнительный контроль над обработкой и мониторингом трафика:

укажите параметр dump-dir для сохранения сырых данных запросов и ответов

используйте traffic-limit для защиты сервера от чрезмерного потребления пропускной способности

установите значение cache-size больше 0 для снижения нагрузки на внешние ресурсы через кэширование GET-запросов

Настройка дампа трафика

```bash
python web.py --dump-dir traffic_dumps
```
Прокси автоматически создаст каталог traffic_dumps и будет сохранять метаданные, тела запросов и ответов в файлы с расширением .dump

Настройка кэширования ответов

```bash
python web.py --cache-size 150 --cache-ttl 600
```
Компонент будет кэшировать только успешные ответы (200 OK), не содержащие запрещающих заголовков вроде no-store, no-cache или private

Настройка лимитера трафика

```bash
python web.py --traffic-limit 104857600
```
Система начнет вести побайтовый учет переданных данных для каждого IP-адреса и заблокирует клиента, если тот превысит лимит в 100 MB

## Core modules usage
Компоненты контроля (ResponseCache, TrafficLimiter, TrafficDumper) работают прозрачно внутри основного цикла обработки соединений класса ProxyServer.

Логика обработки каждого клиентского подключения:

* Быстрая проверка IP-адреса на наличие в черном списке лимитера

* Чтение стартовой строки HTTP-запроса и парсинг параметров назначения

Выбор режима: создание туннеля для метода CONNECT (HTTPS) либо проксирование стандартного HTTP с проверкой кэша

Переменные структуры запроса, доступные при обработке:

* method - метод запроса (GET, POST, CONNECT и др.)

* target_host - целевой хост назначения

* target_port - целевой порт (по умолчанию 80)

## Logging and debug
Если вы хотите использовать стандартный вывод (std.out) как основной информационный канал с цветовой индикацией, добавьте флаг -v или --verbose.

Для сохранения истории сетевых соединений в структурированном виде используется файл, указанный в параметре --log-file (по умолчанию proxy.jsonl), записывающий данные в формате JSON Lines.

При работе на операционной системе Windows прокси-сервер автоматически управляет системными настройками прокси, возвращая их в исходное состояние при корректном завершении работы.
